# tgws для OpenWrt

**Telegram на всех устройствах домашней сети идёт через WebSocket — без настройки на самих устройствах.**

Роутер перехватывает соединения Telegram к его дата-центрам и проводит их через WebSocket
(`kws*.web.telegram.org`). Часто это работает там, где прямое соединение медленное или
заблокировано. Никакого прокси, secret и ссылок `tg://proxy` на телефонах и компьютерах
настраивать не нужно.

Идея и детали протокола — проект [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) (MIT).
Здесь это самостоятельная реализация на Go, которая работает на роутере прозрачно.

## Как это работает

```
устройство в LAN ─TCP→ IP дата-центра Telegram
                         │ nftables: redirect на локальный порт
                         ▼
                       tgws (на роутере)
                         ├─ WebSocket (TLS) → kws{N}.web.telegram.org
                         └─ если WebSocket недоступен — прямой TCP на исходный адрес
```

Если WebSocket не открылся, соединение идёт напрямую, поэтому Telegram не ломается.
Остановка службы снимает правила перехвата первой.

## Установка

Нужен роутер с **OpenWrt 25.12 или новее** (`apk`), LuCI и архитектурой `x86_64`, `aarch64`,
`arm` (любой `arm_*`), `mips` или `mipsel`. Бинарник занимает около 4–5 МБ.

Выполните по SSH **на роутере**:

```sh
sh -c "$(wget -O - https://raw.githubusercontent.com/NooBiToo/tgws-openwrt/main/install.sh)"
```

Затем откройте **Службы → Telegram**, включите ускорение и нажмите **Сохранить и применить**.

## Совместимость с TrustTunnel

Демон ходит к Telegram напрямую, мимо туннеля. Его сокеты помечены `0x7467`;
[luci-app-trusttunnel](https://github.com/NooBiToo/TrustTunnelOpenWrt) возвращает такой трафик
без маркировки в туннель, поэтому при включённом «Трафик роутера через VPN» всё остаётся прямым.
Если у вас в списках TrustTunnel выбран Telegram, при включённом tgws его трафик больше не
пойдёт через туннель: перехват срабатывает раньше.

## Ограничения

- Перехватывается только **IPv4**. Если на роутере включён IPv6, Telegram может подключаться
  по IPv6 и обходить перехват; отключение IPv6 в локальной сети делает ускорение полным.
- Работают только интерфейсы зон фаервола, принимающих входящий трафик к роутеру (обычная
  зона `lan`). Если добавить интерфейс зоны с запретом (`reject`, например гостевой сети),
  fw4 отклонит перенаправленные соединения, и Telegram оттуда не подключится.
- WebSocket по умолчанию открывается только для DC2 и DC4 (как в upstream). Остальные
  дата-центры идут напрямую.
- Клиентам, которые не обфусцируют соединение, дата-центр определяется по адресу назначения
  из короткой таблицы известных адресов. Неизвестные адреса идут напрямую, а их список виден
  на странице LuCI.

## Если что-то не так

```sh
logread -e tgws                 # журнал демона и init-скрипта
nft list table inet tgws        # загружены ли правила перехвата
cat /var/run/tgws.json          # счётчики
/etc/init.d/tgws restart
```

Если не грузятся фото и видео, оставьте в поле «Цели WebSocket» только `4:149.154.167.220`
или введите `none`, чтобы вообще не использовать WebSocket. Пустое поле не подходит: LuCI
удаляет пустую опцию, и подставляются значения по умолчанию.
