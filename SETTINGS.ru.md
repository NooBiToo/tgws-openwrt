# Настройки luci-app-tgws — полный справочник

Все настройки лежат в `/etc/config/tgws`, в единственной секции `main`. В интерфейсе они собраны на
странице **Службы → Telegram → Настройки**, четыре вкладки. Обзорное руководство —
[GUIDE.ru.md](GUIDE.ru.md).

## Как это работает — коротко

Демон `tgws` слушает локальный порт. Правило `nftables` перенаправляет на него соединения устройств
сети к подсетям Telegram. Демон определяет дата-центр и ведёт поток через WebSocket; если не
получилось — повторяет байты клиента дословно прямым соединением (либо через метку, см.
`fallback_mark`).

Настройки читает init-скрипт `/etc/init.d/tgws` при запуске. **Каждое значение проверяется до
запуска**: недопустимое останавливает службу с понятной строкой в журнале (`logread -e tgws`), а не
оставляет демон, который падает и перезапускается каждые 5 секунд.

## Пример файла

```
config tgws 'main'
	option enabled '1'
	option port '5454'
	option dc_ip '2:149.154.167.220,4:149.154.167.220'
	option ip_dc ''
	option lan_devices ''
	option fallback_mark '0x9527'
	option subnets_url ''
```

## Секция `main`

### `enabled` (`0`)

Включена ли служба. `1` — служба при запуске поднимает демон и загружает правила перехвата; `0` —
ничего не делает и снимает правила, если они были. Служба регистрируется для запуска при загрузке
всегда, а решает, работать ли ей, именно эта опция.

Вкладка **Общие**, «Включить». Кнопка **Запустить** на странице «Состояние» запускает службу сразу,
независимо от этой опции.

### `port` (`5454`)

Локальный порт демона. Правило перехвата перенаправляет соединения на него. Допустим любой порт
1–65535. Ведущие нули отбрасываются (`06000` — это `6000`); недопустимое значение заменяется на
`5454` с предупреждением в журнале.

Менять нужно, только если порт занят другой службой: демон тогда не сможет его занять, а правила
не будут загружены (они грузятся лишь после готовности демона).

### `lan_devices` (пусто)

Интерфейсы локальной сети, **трафик с которых перехватывается**, через пробел, например
`br-lan br-guest`. Пусто — устройство сети `lan` (`network.lan.device`), а если и его нет, `br-lan`.

Значение попадает в правила `nftables` в кавычках, поэтому допустимы только буквы, цифры, точка,
дефис, подчёркивание и пробел; любое другое значение отвергается (для генератора правил это
защита от подстановки чужого правила).

**Зона файрвола каждого интерфейса должна принимать входящий трафик к роутеру** (`input ACCEPT`):
иначе `fw4` отклонит перенаправленные соединения, и Telegram из этой сети не подключится. Для
обычной зоны `lan` это выполнено.

### `dc_ip` (`2:149.154.167.220,4:149.154.167.220`)

Цели WebSocket: пары `ДЦ:IP` через запятую. На указанный IP демон открывает WebSocket для данного
дата-центра. Допустимые номера дата-центров: `1`, `2`, `3`, `4`, `5`, `203`. Пример:
`2:149.154.167.220,4:149.154.167.220`.

- Дата-центры, которых здесь нет, идут через откат (напрямую или через `fallback_mark`).
- **`none`** — не использовать WebSocket вовсе, всё идёт через откат. Именно слово `none`, а не
  пустое поле: LuCI удаляет пустую опцию, и подставилось бы значение по умолчанию.
- Если не грузятся фото и видео, попробуйте оставить только `4:149.154.167.220` либо `none`.

По умолчанию — только DC2 и DC4: единственный публично известный адрес `149.154.167.220`
обслуживает именно их. Для DC1, DC3 и DC5 на момент написания достижимого WebSocket-адреса нет.

Значение проверяется дважды: форма LuCI проверяет номер и октеты, а затем демон проверяет его же
командой `tgws -check` перед запуском службы.

### `ip_dc` (пусто)

Ручное соответствие адресов дата-центрам: пары `IP:ДЦ` через запятую, например
`149.154.167.35:2,149.154.167.255:4`.

Нужно только для адресов, которые пакет не смог отнести к дата-центру сам. Android в прямом
соединении **не называет** дата-центр (в заголовке у него мусор), поэтому дата-центр для него
известен только по адресу. Для нового адреса он определяется автоматически перебором; добавляйте
пару вручную, только если адрес постоянно остаётся среди неизвестных на странице «Состояние».

Ручное соответствие сильнее всех остальных способов определения.

### `fallback_mark` (пусто)

Метка (`fwmark`) для соединений, которые **нельзя провести через WebSocket**: веб-страницы Telegram
(`t.me`, `telegram.org`, превью ссылок, мини-приложения), дата-центры без цели в `dc_ip`, HTTP-транспорт.

- Пусто или `0` — такие соединения идут **напрямую**. Без TrustTunnel ничего другого не нужно.
- **`0x9527`** — метка туннеля [TrustTunnel](https://github.com/NooBiToo/TrustTunnelOpenWrt) по
  умолчанию: соединения уходят через его таблицу маршрутов, как и до включения `tgws`. Если вы
  меняли `network.fwmark` в TrustTunnel, укажите свою.

Допустимо шестнадцатеричное (`0x9527`) или десятичное число. Диагностика проверяет, что для метки
есть правило `ip rule`: иначе такой трафик отбрасывался бы.

### `subnets_url` (пусто)

Адрес, откуда раз в неделю обновляется список подсетей Telegram. Пусто — официальный
`https://core.telegram.org/resources/cidr.txt`. Допустимы адреса `http://` и `https://`.

В файл `/etc/tgws/subnets.txt` попадают **только публичные IPv4-подсети** длиной от `/16` до `/32`,
не частные и не служебные (`0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`,
`192.168/16`, `224/4` и выше), в количестве от 3 до 200. Страница с ошибкой, усечённая выдача и чужие
диапазоны отбрасываются, а прежний список остаётся.

Если `core.telegram.org` с роутера недоступен, обновление не удастся, и используется зашитый или
последний скачанный список. Тогда укажите зеркало, доступное роутеру.

Вручную: `/etc/init.d/tgws update_subnets` (или кнопка «Обновить список подсетей» на странице
«Состояние»). Правила перезагружаются, только если список изменился и демон работает.

## Параметры демона

Демон `tgws` запускается init-скриптом; те же значения можно задать флагами при ручном запуске.

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-listen` | `:5454` | где принимать перенаправленные соединения |
| `-dc-ip` | `2:149.154.167.220,4:149.154.167.220` | цели WebSocket (`none` — пусто) |
| `-ip-dc` | пусто | ручное соответствие адресов дата-центрам |
| `-mark` | `0x7467` | `SO_MARK` исходящих соединений демона |
| `-fallback-mark` | `0` (как `-mark`) | метка соединений отката |
| `-stats` | пусто | файл со счётчиками в JSON |
| `-v` | выкл | подробный журнал по каждому соединению |
| `-version` | | напечатать версию |
| `-check` | | проверить `-dc-ip`, `-ip-dc`, `-fallback-mark` и выйти (код 0 — допустимо) |
| `-probe` | | проверить путь до Telegram, JSON в stdout; для него `-dc`, `-media`, `-target` |

Метка `0x7467` у собственных соединений демона нужна, чтобы TrustTunnel с включённым «Трафик
роутера через VPN» не загнал их в туннель; менять её не нужно.

## Счётчики

Демон каждые 5 секунд пишет `/var/run/tgws.json`:

| Поле | Значение |
|---|---|
| `started`, `updated` | время запуска и последней записи (Unix) |
| `active`, `total` | активные и все соединения |
| `ws` | соединения, проведённые через WebSocket |
| `fallback` | соединения, ушедшие в откат |
| `ws_errors` | неудачные попытки открыть WebSocket |
| `bytes_up`, `bytes_down` | байты от клиента и к клиенту |
| `unknown_dc` | адреса, для которых дата-центр не определён (до 32) |

Свежий файл — признак того, что демон работает: он пишется сразу после занятия порта и удаляется
при остановке.
